## Установка

SubBridge запускается одним бинарным файлом со встроенной веб-панелью. На целевой
машине не нужны Go, Node.js, ADB или отдельный процесс Xray.

| Платформа | Архитектуры сборок | Управление сервисом |
| --- | --- | --- |
| Linux | `amd64`, `arm64`, `armv7`, `386` | systemd или OpenRC |
| Windows | `amd64`, `arm64` | Планировщик заданий |

### Linux: установка из архива

Положите архив релиза и соответствующий `checksums.txt` в один каталог.
В примере используется Linux amd64; выберите архив для своего процессора.

```bash
tar -xzf subbridge-v1.1.0-linux-amd64.tar.gz
sudo bash install.sh --archive ./subbridge-v1.1.0-linux-amd64.tar.gz --checksums ./checksums.txt
sudo subbridge credentials
```

Установщик проверяет SHA-256, устанавливает бинарник и консольное меню, создаёт
служебного пользователя `subbridge` и настраивает обнаруженную систему инициализации.
При первой установке сервис запускается, а автозапуск включается, если не передан
параметр `--no-autostart`.

Недостающие утилиты загрузки и распаковки устанавливаются через apt, dnf, yum, apk,
pacman или zypper. На минимальном Alpine сначала установите Bash: `apk add bash`.

### Linux: установка из GitHub Releases

Для сетевой установки и обновления в репозитории должен быть опубликованный релиз.

```bash
curl -fL https://raw.githubusercontent.com/MrTeeett/subbridge/main/install.sh -o install.sh
sudo bash install.sh
```

По умолчанию устанавливается последний стабильный релиз. Для сборки разработки:

```bash
sudo bash install.sh -dev
```

Флаг `-dev` (также `--dev` или `--version dev`) выбирает prerelease `dev` напрямую,
без поиска последнего стабильного релиза. Указывайте либо `-dev`, либо `--version`.
Установщик сохраняет выбранный канал, и консольные обновления продолжают использовать его.

| Параметр установщика | Назначение |
| --- | --- |
| `-dev`, `--dev` | Установить обновляемый prerelease `dev`. |
| `--version v1.1.0` | Установить заданный релиз; по умолчанию выбирается последний. |
| `--repo owner/name` | Использовать другой GitHub-репозиторий. |
| `--archive PATH --checksums PATH` | Установить локальный архив без скачивания релиза. |
| `--no-autostart` | Не включать автозапуск при первой установке. |
| `--stage-dir /absolute/path` | Распаковать и инициализировать в отдельном каталоге без изменения пользователей и служб ОС. |

Обновление сохраняет конфигурацию, HWID, токен подписки и кеш. Уже остановленный
сервис остаётся остановленным; настройка автозапуска также сохраняется.
Если обновление завершается ошибкой после остановки сервиса, установщик возвращает
предыдущие бинарник, консольное меню и описание службы, затем запускает прежний сервис,
если он работал. Параллельные установщики отклоняются. Неудачная первая установка
сохраняет настройки и данные входа для повторной попытки и удаляет незавершённую службу.
Архив и файл контрольных сумм указываются вместе; локальный архив нельзя сочетать
с тегом релиза. Для установки из локального архива curl не требуется.

Если стабильного релиза ещё нет, дождитесь первой успешной сборки Actions и
используйте `-dev`. Ошибки скачивания и проверки суммы не останавливают работающий сервис.

### Windows

Распакуйте ZIP для amd64 или arm64. Откройте PowerShell с правами администратора
и выполните установку из архива. Без `-Archive` и `-Checksums` установщик скачивает
последний релиз с GitHub.

```powershell
.\install.ps1 -Archive C:\Downloads\subbridge-v1.1.0-windows-amd64.zip -Checksums C:\Downloads\checksums.txt
& "$env:ProgramData\SubBridge\subbridge.ps1"
```

Файлы устанавливаются в `%ProgramData%\SubBridge`. Установщик ограничивает ACL каталога
для SYSTEM, администраторов и установившего пользователя. Автозапуск выполняется
задачей **SubBridge** в Планировщике заданий; служба Windows Service не создаётся.

При необходимости используйте `-Version v1.1.0`, `-Repository owner/name`
или `-NoAutostart`. Для сборки разработки — `-Dev` или `-Version dev`.
Пример сетевой установки:

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/MrTeeett/subbridge/main/install.ps1 -OutFile install.ps1
.\install.ps1 -Dev
```

Указывайте либо `-Dev`, либо `-Version`. Консольные обновления сохраняют выбранный канал.
Параметры `-Stage -Destination C:\Temp\SubBridge` позволяют
проверить распаковку и настройку без регистрации задачи. Конфигурация и состояние
сохраняются при обновлении; при неудаче восстанавливается предыдущий EXE.

### Запуск без установки службы

В каталоге с бинарником выполните:

```bash
./subbridge -config config.json -setup
./subbridge -config config.json
```

На Windows используйте `subbridge.exe`. Первичная настройка создаёт недостающие
файлы конфигурации и данные входа. Источник можно оставить пустым и добавить его
позже через веб-панель. Консольное меню управляет установленной службой, но само
не выполняет её установку.

<a id="web-panel"></a>

## Веб-панель

Адрес по умолчанию: **`http://127.0.0.1:8780/admin/`**.

После установки на Linux посмотреть созданные логин и пароль можно командой:

```bash
sudo subbridge credentials
```

Первоначальные данные входа хранятся в `/etc/subbridge/setup-credentials.txt`
с правами `600`. На Windows файл находится в `%ProgramData%\SubBridge\config`.
При запуске без установки — рядом с `management.json`.

На своём компьютере откройте SSH-туннель, затем перейдите по адресу панели:

```bash
ssh -p 22 -L 8780:127.0.0.1:8780 root@SERVER_IP
```

Подставьте SSH-порт, пользователя и адрес своего сервера. Если локальный порт 8780
занят, используйте `-L 18780:127.0.0.1:8780` и откройте
`http://127.0.0.1:18780/admin/`.

В разделе **«Управление панелью»** задаются IP, порт, путь, учётная запись и параметры
SSH-туннеля. SSH-поля формируют команду, но не изменяют настройки SSH-сервера.
Для доступа через туннель оставьте адрес управления на loopback.

Настройки управления находятся в отдельном `management.json`. При изменении адреса
сервис сначала проверяет новый listener. Если IP недоступен или порт занят,
прежний адрес продолжает работать. После успешной смены адреса переподключите
туннель и откройте новый адрес панели.

Смена логина или пароля завершает существующие сессии и удаляет файл первоначальных
данных входа. Пароль хранится как PBKDF2-SHA256 с солью. Для восстановления доступа
выполните `subbridge reset-admin`, затем `subbridge credentials`.

Для HTTPS задайте `tls_cert` и `tls_key` в `management.json` и перезапустите сервис.
При переходе с HTTP на HTTPS используйте свободный порт. Оба файла должны быть
доступны служебному пользователю на чтение.

По умолчанию используется английский язык независимо от языка браузера.
Переключатель **EN / RU** доступен до и после входа. Выбор языка сохраняется
в браузере. Диагностика сервиса отображается на языке оригинала.

<a id="subscriptions-and-hwid"></a>

## Подписки и HWID

В разделе **«Подписки»** задайте название источника и URL или зашифрованную ссылку
импорта, затем сохраните настройки. Кнопка **«Добавить подписку»** создаёт другой источник,
а список сверху переключает редактируемую подписку. Для каждой подписки сохраняются
свой профиль запроса, HWID и кеш. Поддерживается до 32 источников.
**«Удалить подписку»** удаляет источник после сохранения, оставляя его приватные данные
на диске. Для основной подписки очищается URL; её можно восстановить, введя URL снова.

Интервал обновления, профиль экспорта и адрес выдачи общие для всех источников.
По умолчанию обновление выполняется раз в 300 секунд.

Если HWID пустой, сервис создаёт идентификатор из 16 заглавных шестнадцатеричных
символов. Для каждого URL источника сохраняется своя запись. После успешной загрузки
идентификатор повторно используется при обновлениях и после перезапуска.
Введённый вручную HWID автоматически не меняется.

**«Количество попыток HWID»** принимает значения 1–20; по умолчанию — 3.
В число входит первый запрос. Новые кандидаты пробуются после HTTP 403 или
распознанного сообщения о HWID/лимите устройств, с паузой между попытками.
Сетевые ошибки, HTTP 429 и 5xx не вызывают смену идентификатора. Неуспешный кандидат
не заменяет ранее принятый HWID и последний корректный кеш.

Случайный идентификатор соответствует формату v2rayTun, но его принятие определяет
провайдер. Если регистрация закрыта или лимит устройств заполнен, нужен рабочий HWID
либо сброс привязки у провайдера. Смена HWID не снимает ограничения VPN-соединений,
которые проверяет внешний сервер.

Профиль запроса содержит `user_agent`, `hwid`, `device_os`, `os_version`,
`device_model` и `app_version`. User-Agent по умолчанию — `v2raytun/android`.
Общий таймаут обновления составляет 90 секунд: медленный источник может исчерпать
его раньше максимального числа попыток.

Для импорта ранее сохранённого профиля SubBridge:

```bash
./subbridge -init-from-bundle saved.subbridge.json -config config.json
```

Импорт создаёт новую конфигурацию и не перезаписывает существующий файл.
Переносимый файл содержит учётные данные подписки и сведения об устройстве.

### Просмотр конфигов

Раздел **«Конфиги»** в боковом меню раскрывается в **«Все подписки»** и пункты отдельных
источников. Конфиги сгруппированы по подпискам; доступны поиск по названию, серверу,
порту или протоколу и сортировка. У каждого узла можно посмотреть и скопировать URI,
у каждой группы — скопировать свою ссылку подписки и скачать конфиги.

Основная ссылка объединяет источники и убирает дословно совпадающие URI.
У ссылки каждой группы свой постоянный токен с доступом только к этому источнику.
В общей ссылке также можно выбрать источник параметром `source`.
Существующие настройки с одной подпиской и её URL продолжают работать.
Кеши и HWID дополнительных источников находятся в `state/sources/<id>/`,
а данные основной подписки остаются на прежнем месте. Источники обновляются независимо
в пределах таймаута: недоступная подписка сохраняет прежние узлы, пока другие обновляются.

<a id="3x-ui-integration"></a>

## Интеграция с 3x-ui

Используется штатный API внешних подписок клиентов 3x-ui. В панели должны быть
доступны методы `/panel/api/clients/`, включая `externalLinks`.

1. В разделе **3x-ui** укажите базовый URL панели с секретным префиксом, **до `/panel/`**, например
   `https://panel.example:2053/secret-prefix`.
2. Выберите вход по логину/паролю, API-токену или переменным окружения.
3. Нажмите **«Подключиться и загрузить списки»**. Проверяются введённые данные и
   загружаются клиенты и инбаунды без сохранения настроек и изменений в удалённой панели.
4. Выберите клиентов и инбаунды в выпадающих списках. Есть поиск, сортировка,
   множественный выбор и выбор найденных строк. Инбаунды показываются с названием,
   ID, протоколом и портом. Фильтрация не снимает скрытый выбор. После изменений
   в панели нажмите **«Обновить списки»**. Сохранённые записи, которых больше нет
   в ответе панели, остаются отмеченными до ручного снятия выбора.
   Либо отметьте **«Все существующие и будущие клиенты»**.
5. Сохраните подключение и получателей кнопкой **«Сохранить интеграцию»**.
   После изменения получателей окно выбора откроется автоматически. Его также можно
   открыть кнопкой **«Выбрать конфиги»** в разделе **«Добавляемые конфиги»**. Окно автоматически
   загружает разобранные узлы. Между подписками можно переключаться; доступны поиск
   по названию, серверу, порту и протоколу, сортировка, выбор найденных и показ только
   выбранных. Выберите отдельные конфиги, все конфиги источника или все доступные
   конфиги. Нажмите **«Применить выбор»**, чтобы добавить или удалить их в 3x-ui.
   Автосинхронизация обновляет существующие записи; новые конфиги добавляются
   после применения нового выбора.

Имена клиентов и ID инбаундов объединяются. По умолчанию интервал обновления
составляет 60 секунд. При применении выбора учитываются все текущие клиенты
выбранного инбаунда, включая добавленных позже. Эти инбаунды определяют получателей;
раздаваемые конфиги выбираются отдельно. Для добавления узлов в подписку клиента
`admin` выберите этого клиента. Логин самой панели 3x-ui — отдельная учётная запись.

Поле **«Префикс названий узлов»** добавляет текст перед названиями. Оно не выбирает
конфиги и не создаёт инбаунды Xray. Автообновление сохраняет имена существующих записей.

По умолчанию используется **«Передавать конфиги через API»**. Выбранные узлы
сохраняются в 3x-ui как внешние ссылки и обновляются при каждой синхронизации.
Так можно запускать SubBridge на компьютере, а 3x-ui — на удалённом сервере:
входящее подключение от панели к SubBridge не требуется. Изменение выбора удаляет
соответствующие записи SubBridge, в том числе добавленные другим экземпляром.
Посторонние конфиги и ручные записи 3x-ui сохраняются.

Режим **«Добавлять ссылку подписки»** сохраняет выдачу по URL. В нём адрес должен
быть доступен из процесса 3x-ui. `127.0.0.1` означает сервер самой панели, который
может отличаться от компьютера с SubBridge. Смена режима заменяет прежние записи
этого экземпляра. Перед применением сохраните подключение и получателей.
Галочка интеграции управляет автообновлением. Статус под формой показывает
фактическое наличие конфигов в 3x-ui, время проверки и ошибки подключения.

У интеграции свой постоянный адрес подписки, выдающий только выбранные конфиги.
Основная подписка SubBridge и выгрузки отдельных источников сохраняют полный состав.
Пустой выбор выдаёт пустой список, без возврата ко всем узлам. Повторяющиеся URI
объединяются. Недоступные сохранённые записи остаются видимыми в окне, их можно
снять вручную. Отдельный выбор использует название и параметры транспорта узла.
Именованные узлы сохраняют выбор при смене IP или учётных данных провайдером.
Узлы с одинаковыми названиями и транспортом различаются по адресу.
Прежние идентификаторы URI переводятся по кешу. Смена профиля экспорта сохраняет выбор.
После сохранения подключения и получателей кнопка **«Применить выбор»** сохраняет
галочки и запускает разовую синхронизацию. Снятые конфиги удаляются у выбранных
клиентов и при выключенном автообновлении. **«Отмена»** отменяет черновик.
Остальные изменения подключения и получателей сохраняются кнопкой
**«Сохранить интеграцию»**. При применении отмеченные конфиги, которые есть только
у части получателей, добавляются остальным без повторного переключения галочки.
Сохранение получателей и отмена окна не раздают конфиги. Остальные нетронутые
записи, в том числе добавленные другим экземпляром после открытия окна, сохраняются.

### Несколько экземпляров

В режиме передачи через API несколько экземпляров SubBridge могут работать
с одними клиентами 3x-ui без связи между собой. Обновите каждый экземпляр.
Общий источник состояния — API 3x-ui: окно выбора и список конфигов показывают
наличие узла, отсутствие, выключенную запись или наличие только у части получателей.
Кеш проверки хранится до восьми секунд; **«Проверить 3x-ui»** запрашивает свежее
состояние. Ошибка проверки показывает неизвестное состояние и блокирует применение.

Одинаковые подключения объединяются независимо от названий и порядка параметров
URI. Узлы одного источника сохраняют общий идентификатор при смене IP или учётных
данных. Прежние метки импорта переводятся в общий формат без изменения параметров
подключения. Время обновления источника защищает свежие параметры от старого кеша
другого экземпляра. Ручные записи 3x-ui остаются под ручным управлением.

Автосинхронизация обновляет существующие записи и не восстанавливает узлы,
удалённые через другой SubBridge или 3x-ui. Для добавления, в том числе новых узлов
провайдера, используйте **«Применить выбор»**. Первое подключение нового экземпляра
не заменяет удалённый выбор локальными настройками. Режим ссылки подписки
сохраняется для одного экземпляра и не предоставляет такую общую сверку.

Для входа через окружение используются `SUBBRIDGE_PANEL_TOKEN`,
`SUBBRIDGE_PANEL_USERNAME` и `SUBBRIDGE_PANEL_PASSWORD`. В этом режиме токен имеет
приоритет. Пример — `deploy/panel.env.example`; systemd читает файл
`/etc/subbridge/panel.env`. Для учётных записей с 2FA используйте API-токен.
Сохранённые пароль и токен не возвращаются в веб-форму; пустое поле сохраняет
существующее значение.

Для режима ссылки в дополнительных настройках подписки задайте `listen` и `public_url` так,
чтобы полученный адрес был доступен **из процесса 3x-ui**. Для двух сервисов на одном
сервере подходит `127.0.0.1:8770`. У панели в Docker свой loopback; укажите доступный
из контейнера адрес и соответствующий listener.

SubBridge управляет собственными внешними записями, сохраняя остальные строки,
UUID, квоты, сроки клиентов и настройки инбаундов. Повторная синхронизация не создаёт
дублей и не включает строку, выключенную вручную. Существующая запись SubBridge со
старым общим адресом переводится на отдельный адрес интеграции. Снятие клиента с выбора не удаляет
ранее добавленную строку. После изменения `public_url` старую строку в 3x-ui нужно
удалить вручную.

Внешние узлы появляются в подписке пользователя. Они не становятся локальными
инбаундами Xray: трафик идёт напрямую к провайдеру. Локальные лимиты 3x-ui
не управляют этими внешними учётными данными. Raw/Base64 сохраняет расширенные
параметры URI; JSON и Clash дополнительно зависят от импортера самой 3x-ui.

При обновлении API 3x-ui заменяет весь список внешних ссылок. SubBridge перечитывает
его перед записью, но одновременное ручное редактирование всё равно может вызвать
конфликт. Панель также может кешировать внешние подписки, задерживая появление изменений.

<a id="console-management"></a>

## Консольное управление

На Linux команда `sudo subbridge` открывает английское меню. Каждый пункт расположен
на отдельной строке; **`0. Exit`** завершает работу. Ошибка команды или отмена удаления
возвращает к меню. Для управления службой она должна быть установлена.

| Команда | Действие |
| --- | --- |
| `subbridge start` | Запустить сервис. |
| `subbridge stop` | Остановить сервис. |
| `subbridge restart` | Перезапустить сервис. |
| `subbridge status` | Посмотреть состояние службы. |
| `subbridge logs` | Показать последние 100 строк журнала. |
| `subbridge update` | Обновить из сохранённого канала stable или dev. |
| `subbridge update -dev` | Установить или выбрать обновляемую сборку разработки. |
| `subbridge update --version latest` | Установить или выбрать последний стабильный релиз. |
| `subbridge update --version v1.1.0` | Установить заданный релиз. |
| `subbridge enable` | Включить автозапуск. |
| `subbridge disable` | Выключить автозапуск, сохранив текущий запуск. |
| `subbridge settings` | Изменить IP, порт или логин панели и перезапустить сервис. |
| `subbridge reset-admin` | Создать новый пароль панели и перезапустить сервис. |
| `subbridge credentials` | Показать первоначальные или сброшенные данные входа. |
| `subbridge management` | Показать настройки управления без хеша пароля. |
| `subbridge url` | Вывести приватный URL подписки. |
| `subbridge check` | Проверить конфигурацию без сетевых запросов. |
| `subbridge uninstall` | Удалить бинарники и службу, сохранив конфигурацию и состояние. |

Административные команды требуют root. Удаление запрашивает подтверждение,
если не указан `--yes`. Для полного удаления личных данных отдельно удалите
соответствующие каталоги после остановки сервиса.

На Windows откройте `subbridge.ps1` для меню или передайте одну команду, например:

```powershell
& "$env:ProgramData\SubBridge\subbridge.ps1" -Command restart
```

Для перехода на dev используйте `-Command update -Dev`, для возврата на stable —
`-Command update -Version latest`. Без версии `-Command update` сохраняет выбранный канал.

Доступны `start`, `stop`, `restart`, `status`, `logs`, `update`, `enable`, `disable`,
`settings`, `reset-admin`, `credentials`, `management`, `url`, `check` и `uninstall`.
Для операций с задачей Планировщика нужны права администратора.

<a id="configuration-and-stored-data"></a>

## Конфигурация и данные

Источник, экспорт и 3x-ui настраиваются в `config.json`. Доступ к панели и учётная
запись — в отдельном `management.json`.
См. [пример конфигурации](../deploy/config.example.json).

| Данные | Установка Linux | Установка Windows |
| --- | --- | --- |
| Основная конфигурация | `/etc/subbridge/config.json` | `%ProgramData%\SubBridge\config\config.json` |
| Настройки управления | `/etc/subbridge/management.json` | `%ProgramData%\SubBridge\config\management.json` |
| Первоначальные данные входа | `/etc/subbridge/setup-credentials.txt` | `%ProgramData%\SubBridge\config\setup-credentials.txt` |
| Постоянное состояние | `/var/lib/subbridge` | `%ProgramData%\SubBridge\state` |
| Бинарник сервиса | `/usr/local/lib/subbridge/subbridge-core` | `%ProgramData%\SubBridge\subbridge.exe` |
| Консольное меню | `/usr/local/bin/subbridge` | `%ProgramData%\SubBridge\subbridge.ps1` |

Состояние включает `token`, `cache.json` и `hwid.json`. Файлы сохраняются через
временный файл с последующим переименованием. Сохранение токена позволяет оставить
прежний URL подписки. При сбое источника остаётся последний корректный кеш,
в том числе после перезапуска. Смена URL или профиля запроса исключает использование
кеша предыдущего источника.

В каталоге установленного бинарника также находятся `repository` и `release-channel`,
которые консоль использует для обновлений. Для прежних установок без сохранённого
канала по умолчанию выбирается stable.

На Linux файлам с секретами нужны права `600`, каталогу состояния — `700`.
На Windows используются ACL; проверки POSIX-прав не применяются. Установщики
настраивают эти права автоматически. Другой каталог состояния задаётся через
конфигурационный файл и перезапуск сервиса, а не веб-форму.

### Параметры бинарника

Используйте их с отдельным бинарником либо передавайте через `subbridge run`
в установленной Linux-версии.

| Параметр | Действие |
| --- | --- |
| `-config PATH` | Выбрать файл основной конфигурации. |
| `-management-config PATH` | Выбрать отдельный файл управления. |
| `-setup` | Создать недостающие настройки и данные входа. |
| `-no-web` | Отключить веб-управление на этот запуск. |
| `-admin-ip IP`, `-admin-port PORT`, `-admin-username NAME` | Сохранить настройки управления и завершить процесс. |
| `-reset-admin` | Сохранить случайный пароль панели и завершить процесс. |
| `-admin-password-env NAME` | Прочитать новый пароль из указанной переменной окружения. |
| `-check` | Проверить настройки и встроенные ключи без сети. |
| `-dry-run` | Загрузить и кешировать источник, проверить выбор клиентов, не записывая изменения в 3x-ui. |
| `-once` | Однократно обновить источник, выполнить синхронизацию и завершить процесс. |
| `-print-url` | Вывести приватный URL подписки и завершить процесс. |
| `-log-file PATH` | Дополнительно записывать диагностику в приватный файл. |

После изменения файлов управления через CLI перезапустите уже работающую службу.
Для выдачи подписки процесс должен оставаться запущенным. Обычный журнал не содержит
URL источника, идентификаторы устройств, UUID клиентов и секреты панели.

<a id="export-formats"></a>

## Форматы выгрузки

Приватный адрес `/sub/<token>` выдаёт стандартные URI. Через веб-панель можно
скачать все конфигурации или только записи VLESS.

| Параметр URL | Значения |
| --- | --- |
| `format` | `raw` по умолчанию, `base64` |
| `profile` | `original`, `v2rayn` |
| `protocol` | `all` по умолчанию, `vless` |
| `source` | ID источника; без параметра объединяются все источники. ID основной подписки — `default`. |

`original` дословно сохраняет исходные URI, включая `pqv`, `extra`, `encryption`,
неизвестные и повторяющиеся query-параметры. `v2rayn` меняет только `fp=qq`
на `firefox` для VLESS REALITY, не затрагивая исходный кеш. Для некоторых мобильных
подключений нужен исходный fingerprint, поэтому по умолчанию выбран `original`.

Поддерживаются Xray JSON/JSONC, списки URI, Base64, зашифрованные ссылки v2rayTun
и Happ. Выгрузка включает VLESS, VMess, Trojan, Shadowsocks, SOCKS/HTTP и Hysteria 2.
DNS, маршрутизация, цепочки и отдельные транспортные настройки JSON не представляются
одним URI; панель сообщает об особенностях преобразования.

Ограничения: 32 источника, по 8 МиБ и до 10000 узлов на источник, 2 МиБ на общий результат при включённой
интеграции с 3x-ui. Ответы провайдера с адресами-заглушками не заменяют корректный кеш.

<a id="troubleshooting"></a>

## Устранение неполадок

| Симптом | Что проверить |
| --- | --- |
| `Unit subbridge.service could not be found` | Установите службу через `install.sh`. Запуск консольного скрипта сам по себе её не создаёт. |
| Панель не открывается | Проверьте IP, порт, путь и обе стороны SSH-туннеля. На сервере выполните `subbridge status` и `subbridge logs`. |
| Новый адрес панели отклонён | Убедитесь, что IP назначен серверу, а порт свободен. После неудачной смены прежний listener остаётся доступным. |
| Попытки HWID исчерпаны | Введите известный рабочий HWID или проверьте привязку и квоту устройств у провайдера. |
| Источник недоступен, но старые узлы остались | Выдаётся последний корректный кеш. Посмотрите ошибку и время успешного обновления в «Обзоре». |
| Узлы не появились в 3x-ui | Проверьте вход, выбор клиентов, секретный префикс URL, поддержку API внешних ссылок и доступность `public_url` из 3x-ui. |
| Компьютерный клиент не работает с `fp=qq` | Попробуйте профиль экспорта `v2rayn`, сохранив оригинал для мобильных клиентов. |
| Linux отклоняет файл конфигурации | Проверьте права `600`, права каталога состояния `700` и доступ служебного пользователя. |

<a id="development"></a>

## Разработка

Нужен **Go 1.26.x**. Используется стандартная библиотека; веб-панель встроена
и не требует Node.js или отдельной сборки фронтенда. Локальным скриптам сборки
нужны Linux, cgroup v2 и systemd. Для race-тестов также нужен C-компилятор.

В каталоге исходников выполните:

```bash
./test.sh
./build.sh all
./package.sh
```

Скрипты применяют и проверяют жёсткий лимит ОС не выше 4 ГиБ для всего дерева
процессов, отключают swap в scope и выполняют сборку без параллельных заданий.
Дополнительно задаются `GOMAXPROCS=1`, `GOMEMLIMIT=2GiB`, `GOFLAGS=-p=1`
и `GOTOOLCHAIN=local`. Если лимит cgroup нельзя установить и проверить,
компиляция не начинается. Ограничение Go heap дополняет лимит ОС.

`test.sh` запускает `go vet` и race-тесты. `build.sh` создаёт статические бинарники
с отключённым CGO. Для одной цели используйте `./build.sh windows-amd64` или другое
имя сборки. Версия в бинарнике и архивах задаётся через `SUBBRIDGE_VERSION=1.1.0`.
Для dev-сборки задайте версию вида `1.1.0-dev.local`, а при упаковке —
`SUBBRIDGE_RELEASE_TAG=dev`. Имена dev-архивов остаются
`subbridge-dev-<платформа>-<архитектура>`, а бинарник сохраняет полную версию.

В `dist/releases` находятся tar.gz для Linux, ZIP для Windows, архив исходников
и `checksums.txt`. В архивы включена документация на обоих языках.
Упаковщик написан на Go и использует явные списки файлов для релизов.

Workflow `.github/workflows/release.yml` запускается при push, pull request и вручную.
Он последовательно собирает цели, проверяет Linux-бинарники на Ubuntu 22.04/24.04
и Alpine, а также задаёт нативные проверки Windows Server 2022/2025.
Сборка и тесты Windows выполняются в Job с проверенным лимитом 4 ГиБ;
Go-супервизор предварительно компилируется в ограниченном Linux-задании.

Каждый push в любую ветку собирает dev-версию с commit SHA. После успешных проверок
создаётся или обновляется prerelease `dev`, а его Git-тег переносится на собранный
коммит. Новый push ветки отменяет незавершённую dev-сборку. Pull request создаёт
артефакты сборки без публикации релиза.

Push тега версии, например `v1.1.0`, публикует этот релиз после успешных проверок.
Prerelease `dev` не отмечается как последний стабильный релиз. Используется штатный
`GITHUB_TOKEN`; отдельная учётная запись бота не нужна.

Тесты охватывают расшифровку, протоколы, заголовки, лимиты, попытки HWID, сохранение
кеша, отмену запросов, конкурентную работу, вход в панель, CSRF, откат смены адреса
и контракт API 3x-ui. `scripts/check-install.sh` проверяет установку в отдельный
каталог, обновление, отклонение неверной суммы и удаление без изменения служб хоста.
`scripts/check-release.sh` проверяет скачивание stable/dev, сохранение каналов
и публикацию релизов через локальные имитации curl и GitHub CLI без обращения к сети.
`scripts/check-selection.mjs` проверяет выбор для нескольких получателей,
частичное наличие и удаление через другую панель. Для этой проверки нужен Node.js
22 или новее; для запуска самого SubBridge он не требуется.
`scripts/check-install-services.sh` проверяет права служебного пользователя,
ошибки запуска, полный откат установки, блокировку и сохранение состояния службы
с имитацией команд systemd/OpenRC в одноразовых Docker-контейнерах.
Интеграционные проверки используют локальную тестовую панель; совместимость
с вашим провайдером и панелью проверяется при развёртывании.
